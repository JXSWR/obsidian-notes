> ⚠️ 与 `20_专业领域/01_非标设计/05.1_参考案例库/`（小丸子课程案例·非亲历）**严格分开**：
> 那边是「别人做的设备长什么样」，这边是「我做的项目踩过什么坑」。**两边不互相归档。**

---

## 区域规则

### 什么放这里

- 进行中的非标设计项目（10天~1个月周期）
- 跨领域项目（同时涉及设计+数控+其他）
- 新项目的初期调研、方案构思
- **已完成的项目** —— 原样保留，这是资产不是垃圾

### 什么不放这里

- ❌ 领域知识 —— 归 `20_专业领域/01_非标设计/` `20_专业领域/02_数控编程/`
- ❌ 从项目提炼出的可复用结构 —— 归 `20_专业领域/01_非标设计/07_可复用卡/`
- ❌ 日常笔记 —— 归对应知识域

### 两类项目，不要混

| | 本人项目（本目录） | 参考案例（`05.1_参考案例库/`） |
| :--- | :--- | :--- |
| 来源 | 自己做的 | 小丸子课程 |
| 价值 | **过程**：怎么想的、卡在哪、怎么解的 | **结果**：设备长什么样、什么机构 |
| 复盘 | 可填，且是全库最值钱的部分 | 结构性不可填 |
| 提炼产物 | **A · 亲历验证**，可直接抄 | **B · 课程提炼**，用前留个心眼 |

### 生命周期

```
项目启动 → 50_项目实践/01_项目开发/YYYY-MM-项目名-序号/
               │                        ← 在这里工作
               │
进行中    → 记录决策与疑点              ← 疑点就是将来决策卡的素材
               │
项目完成  → 原地结项，目录保留            ← 不删除、不搬走
               │
               ├→ 可复用结构 → 20_专业领域/01_非标设计/07_可复用卡/（标 A 级）
               │
               ├→ 成品案例 → 20_专业领域/01_非标设计/05.2_自建案例库/
               │              **链接回本目录的笔记，不复制内容**
               │
               └→ 结项摘要 → 留在项目目录内
```

> **本目录 与 `05.2_自建案例库/` 的分工（2026-09-04 定）**：
>
> | | 本目录（过程工作台） | `05.2_自建案例库/`（成品案例） |
> | :--- | :--- | :--- |
> | 时机 | 项目进行中 | 项目阶段性完成后 |
> | 内容 | 疑点、方案演变、拆机照片、资料索引、草稿 | 项目简介 / 模型说明 / 可复用提取 / 复盘 |
> | 性质 | 一手记录，可乱 | 结构化成品，可读 |
>
> 两边用**链接互指**，内容只存一处。复制必漂移——同一件事在两个地方会写成两个版本。
> 项目进行中不要去 `05.2` 建案例，等沉淀时再建。

> **为什么不再「提炼完就删」**：旧规则要求项目完成后把案例搬进知识库、删掉项目目录。
> 那对「整理」有效，对「积累」有害——一手的过程记录（决策依据、疑点、返工）删了就没了，
> 剩下的二手摘要会失去可信度来源。**项目目录本身就是资产。**
