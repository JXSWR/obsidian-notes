# 📖 术语速查

> AI 工具 + Git 常用黑话。目的是**看对话不懵、提需求更准**。
> 用法：不用背，遇到看不懂的词回来查；会用的词直接跟 AI 说，能省一大段解释。

---

## ⭐ 最高频 8 个（一周至少碰一次）

| 词 | 全称 / 中文 | 一句话 | 什么时候碰 |
| :--- | :--- | :--- | :--- |
| **cwd** | Current Working Directory | AI 现在**站在哪个文件夹** | 决定哪套规则生效，最关键 |
| **pwd** | Print Working Directory | 命令：打印当前目录 | 想确认 AI 在哪，就发 `pwd` |
| **deny** | 拒绝 | 黑名单规则，**优先级最高** | 硬拦截写保护目录 |
| **commit** | 提交 | 存一个档（快照） | 同步 GitHub 前必做 |
| **push** | 推送 | 上传到 GitHub | 备份 / 发布 |
| **branch** | 分支 | 一条独立工作线 | 你的主分支叫 `master` |
| **rule** | 规则 | 自动加载的约束文件 | 让 AI 守你的规矩 |
| **agent** | 子代理 | 分工干活的分身 | 你那 3 个：cnc-programmer 等 |

## 1️⃣ 路径 / 工作空间

| 词 | 全称 / 中文 | 一句话 |
| :--- | :--- | :--- |
| **path** | 路径 | 文件地址 |
| **绝对路径** | — | 完整地址：`d:\My knowledge vault\10_手册\x.md` |
| **相对路径** | — | 从当前目录算：`10_手册\x.md` |
| **workspace** | 工作空间 | 你给 AI 选的那个根文件夹 |
| **repo / repository** | 仓库 | 被 git 管理的整个文件夹 |
| **worktree** | 工作树 | 一个仓库在多个目录同时展开的"分身" |
| **HEAD** | — | 指针，标记"你当前在这儿" |

## 2️⃣ 权限（你的护栏）

| 词 | 中文 | 一句话 |
| :--- | :--- | :--- |
| **deny** | 拒绝 | 黑名单，**优先级最高**，拦住就拦住 |
| **allow** | 允许 | 白名单，免询问放行 |
| **permission** | 权限 | 总称 |
| **read-only** | 只读 | 能看不能改 |

> 你 vault 的 `60_存档/`、`_原始资料/`、`.git/` 就靠 `deny` 硬拦。

## 3️⃣ Git / GitHub（同步 vault 全靠它）

| 词 | 中文 | 一句话 |
| :--- | :--- | :--- |
| **commit** | 提交 | 存一个档，写好说明文字 |
| **push** | 推送 | 上传到 GitHub |
| **pull** | 拉取 | 从 GitHub 下载最新 |
| **branch** | 分支 | 一条独立工作线，互不干扰 |
| **master / main** | 主分支名 | **你的叫 `master`**（不是 main） |
| **merge** | 合并 | 把一条分支并入另一条 |
| **remote** | 远程 | GitHub 上的那份 |
| **origin** | — | 远程仓库的默认代号（`git push origin master`） |
| **clone** | 克隆 | 把远程整个下载到本地 |
| **status** | 状态 | 有哪些改动还没提交 |
| **diff** | 差异 | 具体改了哪些内容 |
| **untracked** | 未跟踪 | 新文件，还没进 git |
| **staged** | 已暂存 | 已 `git add`，等着被提交 |
| **conflict** | 冲突 | 两边改了同一处，要人工选 |
| **prune** | 清理 | 清掉失效的登记记录 |
| **.gitignore** | 忽略清单 | 列进去的文件永远不进 git |
| **LFS** | Large File Storage | 大文件（>10MB）单独存，不撑爆仓库 |
| **SSH** | 安全外壳协议 | 你连 GitHub 用的那把钥匙 |
| **index** | 索引 = 暂存区 | staged 文件的存放地；「git 索引里有」= 这文件有备份 |
| **checkout** | 检出 / 恢复 | 把索引或历史里的文件写回磁盘（`checkout-index` 能恢复被删文件） |
| **rename** | 重命名 | git 能自动识别「文件移动 + 改名」，历史不丢（如 `05.2` → `05.2_`） |
| **ls-files** | 列跟踪文件 | 查哪些文件已被 git 登记 |
| **reflog** | 操作流水 | 每次存档点移动的日志；误删/误操作后找线索用 |
| **fsck** | 仓库体检 | 查 git 有无损坏、悬空对象 |
| **dangling** | 悬空对象 | 重写历史后留下的孤儿残留（**别乱清**） |
| **gc** | 垃圾回收 | ⚠️ 清残留用；**你这台机器跑它会毁仓库，别用** |
| **reset** | 回退 | `reset --soft` 撤销提交但保留改动（可逆） |
| **force push** | 强推 | 覆盖远程历史（重写历史后才需要，慎用） |

## 7️⃣ 文件 / Obsidian

| 词 | 中文 | 一句话 |
| :--- | :--- | :--- |
| **MD5** | 文件指纹 | 一段固定长度的"内容摘要"；两文件 MD5 相同 = 内容完全一致（迁移校验靠它） |
| **mtime** | 修改时间 | 文件最后一次被改的时间，查"谁什么时候动过文件" |
| **wikilink** | 双链 `[[ ]]` | Obsidian 笔记互链；按**文件名**解析，所以文件搬家链接不断 |
| **trash / 回收站** | 删除去向 | Obsidian 默认删进**系统回收站**；回收站清空 = 永久删除（git 没跟踪就真没了） |

## 💡 真正的用处：用这些词跟我说话

不用背，但**提需求时带上关键词，我能少猜、更快给准答案**：

| 普通说法 | 带术语的说法 | 差别 |
| :--- | :--- | :--- |
| "你在哪个文件夹干活？" | "`pwd`" | 一条命令出结果 |
| "别让它动存档" | "给 `60_存档` 加 `deny`" | 我直接改配置，不用解释半天 |
| "保存一下传到网上" | "`commit` 再 `push`" | 明确两步，不会漏 |
| "让那个数控分身干" | "用 `cnc-programmer` agent" | 精确点名 |
| "改一下配置文件" | "改 `settings.json`" | 我直接定位文件 |
