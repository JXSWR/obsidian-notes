## 二、可操作步骤（命令示例）

- 安装并初始化 Git LFS（只需一次）：

  git lfs install

- 为未来的二进制文件添加 LFS 跟踪（示例）：

  git lfs track "*.pptx" "*.mp4" "*.pdf" "*.xmind"
  git add .gitattributes
  git commit -m "Add Git LFS tracking for large binary types"

  （说明：上述只影响之后的提交，不会自动把已存在的历史文件转为 LFS）

- 查看仓库对象与大小统计：

  git count-objects -vH

- 查看 .git 大小（Windows PowerShell 示例）：

  Get-ChildItem .git -Recurse | Measure-Object Length -Sum

- 若决定迁移历史中的大文件到 LFS（会重写历史，务必先备份并通知合作者）：

  git lfs migrate import --include="*.pptx,*.mp4,*.pdf,*.xmind" --everything

  重大警告：迁移会改写历史，迁移后所有人需重新克隆仓库，且可能影响 PR/issue 历史引用。

## 三、关于 .gitignore（针对 Obsidian 的建议）

- 当前仓库将整个 `.obsidian/` 忽略，会把 Obsidian 的全部配置、主题、插件设置排除。通常建议更精细地忽略只排除本地易变/敏感文件，保留希望跨设备同步的设置（如主题、community-plugins 列表等）。

- 推荐示例（替代整体忽略）：

  # 忽略工作区状态（本地）
  .obsidian/workspace
  .obsidian/workspace.json

  # 忽略本地插件状态（视插件而定）
  .obsidian/plugins/*/local-*

  # 保留（示例）——若希望在多设备同步主题与插件列表，则取消注释这些行：
  # .obsidian/community-plugins.json
  # .obsidian/snippets/

- 根据你的同步需求调整。若更偏向“跨设备完整同步”，可保留更多 `.obsidian` 内的文件；若更偏向隐私/本地化，则继续忽略整个目录。

## 五、长期策略（流程 + 自动化）

1. 文档化仓库维护规范：在仓库根添加 REPOSITORY.md 或 MAINTENANCE.md，说明哪些文件允许入库、LFS 策略、备份频率与恢复步骤。

2. 将 .gitattributes 与 .gitignore 作为策略文件提交，所有协作者遵守。

   - 使用脚本自动化：git bundle 或 git clone --mirror 并同步到云盘/NAS。

4. 周期性检查仓库体积与大文件：

5. 恢复与迁移流程准备：
   - 若未来决定执行 `git lfs migrate`，提前准备好迁移说明文档（步骤、备份位置、通知清单），并在迁移窗口内执行。

## 六、风险与注意事项

- GitHub 虽可靠，但不是唯一备份。建议至少维持两份以上不同介质的备份（远程仓库 + 本地离线硬盘或另一云端）。

- 改写历史（如 lfs migrate）有破坏性，迁移前务必备份并协调其他协作者。

- 不要把敏感文件（私钥、token、密码）提交到仓库；如果不慎提交，按 GitHub 指南立刻撤销/替换并旋转密钥。
