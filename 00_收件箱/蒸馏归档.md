> **一句话**：收件箱的「蒸馏车间」。每次整理时，把原始素材**提炼成结构化笔记**，按目的地模板归位——不是搬文件，是变废为宝。
>
> 2026-09-04 建立。

## 一、触发时机

- 用户说「整理收件箱」→ 执行本流程
- 目标：收件箱清空或接近空（< 5 条）
- AI **不主动**检索收件箱（沿用 README 规则）

## 二、第一步：先分类，不急着蒸馏

不是所有收件箱条目都要写成笔记。**先判五类**，判错类比蒸馏错更糟：

| 类型           | 判据                        | 处置                                                                 |
| :----------- | :------------------------ | :----------------------------------------------------------------- |
| **A · 已覆盖**  | 库内已有笔记完整覆盖此内容             | 不新建。处理记录登记一行 + 原文处置                                                |
| **B · 原文归档** | 外来好文章 / 截图 / 聊天记录，本身是素材   | 不二次加工。原文 → 目标域 `_原始资料/`（写保护冷存区，用户手拖），可选在相关笔记加一行索引 |
| **C · 蒸馏成稿** | 有信息增量、能套模板成结构             | 走第三节流程＋删除原文                                                        |
| **D · 无法蒸馏** | 内容不足 / 缺上下文（一句话想法）        | 不硬写。标注「待用户补充：___」，宁缺毋滥（TODO ≠ NA）                                  |
| **E · 行动项**  | 是要做的事，不是知识（如「能否把 X 打包出售」） | 转项目 TODO，不建知识笔记                                                    |

> 判断实例：`cimatron 二次开发打包出售` = E（产品化已在推进，见 [[09_cimatron二次开发记录]]）；
> `用 skill 做自媒体 vs 自己学` = A（与既有主题笔记重复，不新建；`蒸馏skill引发的思考` 已由用户清理）。

## 三、C 类（蒸馏成稿）五步流程

```
1. 读原文，判去向（下表）＋ 判分类（上表）
2. 按目的地模板蒸馏 → 内容草稿
3. 产出分拣单：每条 = 原文摘要 / 去向 / 模板 / 草稿 / C级判断点 / 原文处置
4. 用户过目 → 点头或改
5. 按确认结果落盘 + 登记 [[处理记录]] + 处置原文 + 收件箱减条
```

**分拣单确认制是硬规则**：AI 蒸馏出的内容天然是 C 级（推算），未经用户确认不得落进知识库。这是「来源等级 A/B/C」体系在收件箱环节的闸门。

## 五、原文处置规则（落盘确认时一并执行）

| 原文类型 | 处置 | 谁执行 |
| :--- | :--- | :--- |
| 外来素材（好文章/截图） | → 目标域 `_原始资料/`（写保护冷存区，留底可溯源） | AI |
| 自己的随手记（**随笔记.md 除外**，见守则 5） | 内容并入成稿后，原文条目删除 | AI |
| 无用的 | 删除 | AI |

> ⚠️ `60_存档/` 是 permissions.deny 硬拦截区，**AI 不能写入**；需归档到那里时，
> 分拣单会给目标路径，拖放动作由用户完成。
> （`_原始资料/` 冷存区 2026-09-04 同日已重建，恢复为合法落点。）

## 六、蒸馏守则（红线）

1. **不编造**：数值、案例、判断没有依据就标「待补」或「C 级待验证」，不硬填
2. **只链不抄**：同一数值/结论只写一处，其他笔记用 wikilink 指向它（防两处漂移）
3. **不重复造轮子**：先查库内是否已覆盖（第二步 A 类），覆盖了就登记不新建
4. **TODO ≠ NA**：素材没提供 ≠ 欠债，记「待用户补充」，不制造虚假任务
5. **随笔记.md 永久豁免**：`00_收件箱/随笔记.md` 是用户私人随手记，**独立存在**——不参与本流程、不建任何链接、条目永不删除。整理收件箱时直接跳过它。
